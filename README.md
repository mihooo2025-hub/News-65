# 365Scores → Gemini → WordPress Drafts → Telegram

مشروع Python عام وقابل للنشر على GitHub لجلب أخبار كرة القدم الحديثة من صفحة 365Scores العربية، استخراج النص والصورة البارزة من صفحة الخبر، إعادة الصياغة عبر Gemini API من Google AI Studio، اختيار التصنيفات المسموحة، ثم إنشاء الخبر كمسودة في WordPress وإرسال تقرير إلى Telegram.

## آلية العمل

1. يعمل GitHub Actions مرة كل ساعة.
2. في كل دورة يفحص آخر 6 ساعات.
3. يجمع روابط الأخبار الظاهرة في صفحة الأخبار مع التمرير داخل الصفحة لتوسيع القائمة.
4. يفتح كل خبر ويشترط وجود نص وصورة بارزة قابلة للجلب. الخبر الذي لا يملك صورة بارزة يُسجّل كمُتجاهَل بسبب الصورة ولا يُعاد إدخاله في كل دورة.
5. الأخبار التي تفشل مؤقتًا في التحليل أو إعادة الصياغة أو WordPress لا تُعلّم كمُعالجة، لذلك تعود تلقائيًا في الدورة التالية.
6. لمنع التكرار حتى لو فقد ملف الحالة، يستخدم المشروع slug ثابتًا مبنيًا على hash لرابط المصدر ويتحقق من وجوده في WordPress قبل إنشاء المسودة.
7. بعد نجاح إعادة الصياغة ينتظر 5 ثوانٍ قبل محاولة إنشاء المسودة.
8. بعد إنشاء كل مسودة ينتظر 5 ثوانٍ قبل معالجة الخبر التالي.
9. لا تُنشأ تصنيفات جديدة. يتم استخدام التصنيفات الموجودة فقط، مع إضافة `Uncategorized` دائمًا لكل مسودة.
10. بعد انتهاء الدورة يُرسل تقرير واحد إلى Telegram يتضمن عناوين الأخبار الجديدة وروابط الأخبار الأصلية.

## مهم بخصوص Gemini المجاني

المشروع يستخدم Gemini API عبر Google AI Studio. حاليًا توجد نماذج ضمن Free Tier، لكن الحدود والحصص يمكن أن تتغير. النموذج الافتراضي في المشروع هو `gemini-3.1-flash-lite` ويمكن تغييره من GitHub Secrets. راجع صفحة الأسعار الرسمية من Google قبل الاعتماد التشغيلي طويل المدى.

## المتطلبات

- مستودع GitHub عام أو خاص.
- GitHub Actions مفعّل.
- مفتاح Gemini API من Google AI Studio.
- WordPress مع REST API و Application Password للمستخدم الذي سيُنشئ المسودات.
- Telegram Bot Token و Chat ID.

## GitHub Secrets المطلوبة

أضف الأسرار التالية من Settings → Secrets and variables → Actions → New repository secret:

### المصدر

`SOURCE_URL`

ضع رابط صفحة الأخبار العربية التي تريد فحصها، مثل رابطك الحالي للمصدر. لا يوجد هذا الرابط داخل الكود.

### Gemini

`GEMINI_API_KEY`

اختياري:

`GEMINI_MODEL`

الافتراضي: `gemini-3.1-flash-lite`

### WordPress

`WP_BASE_URL`

رابط موقع WordPress فقط، مثل `https://example.com`.

`WP_USERNAME`

اسم مستخدم WordPress.

`WP_APP_PASSWORD`

Application Password للمستخدم.

### Telegram

`TELEGRAM_BOT_TOKEN`

`TELEGRAM_CHAT_ID`

### التصنيفات

يمكن ترك التصنيفات الافتراضية في `config.py` كما هي لأنها مبنية فقط على القائمة التي زوّد بها المشروع. ويمكن بدلًا من ذلك تمرير JSON عبر:

`ALLOWED_CATEGORIES_JSON`

مثال:

```json
["سوق الانتقالات","ريال مدريد","برشلونة","ليفربول","مانشستر يونايتد","مانشستر سيتي","تشيلسي","ارسنال","بايرن ميونخ","باريس سان جيرمان","ميلان","يوفنتوس","انتر ميلان","بوروسيا دورتموند","اتليتكو مدريد","Uncategorized"]
```

العناصر المستبعدة تلقائيًا مهما كانت نتيجة Gemini:

- `اهم الاخبار`
- `مقالات وتحليلات`

ولا يمكن للمشروع إنشاء تصنيف جديد.

## تشغيل يدوي

من تبويب Actions شغّل workflow باسم `Publish football news` واختر `Run workflow`.

يمكن تشغيل البرنامج محليًا بعد تثبيت المتطلبات:

```bash
pip install -r requirements.txt
playwright install chromium
python main.py
```

## ملفات الحالة

يحتوي `data/state.json` على hashes وحالة المعالجة فقط، وليس روابط المواقع أو كلمات المرور أو مفاتيح API. لا تحفظ الأسرار داخل المستودع.

## ملاحظات تشغيلية

- GitHub Actions يستخدم UTC، لذلك إعداد workflow هو مرة كل ساعة عند الدقيقة 17 لتقليل احتمال تأخر الجدولة في بداية الساعة.
- إذا لم يحصل المشروع على صورة بارزة من المصدر، يتم تجاهل الخبر لهذه الدورة وتسجيل السبب كـ `skipped_no_image`.
- إذا حصل فشل مؤقت، لا يتم تسجيل الخبر كنجاح، وبالتالي سيعود في دورة لاحقة.
- يتم إرسال تقرير Telegram حتى في حال وجود أخطاء جزئية.
