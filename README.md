# بوت نبض الملاعب — سحب من 365scores

مشروع أتمتة: يسحب الأخبار من `365scores.com/ar`، يعيد صياغتها عربيًا عبر Gemini
(Google AI Studio، مجاني)، وينشرها كمسودة في ووردبريس مع تقرير تلجرام بعد كل دورة.

## طريقة الإعداد

### 1. رفع المشروع إلى GitHub
أنشئ مستودع جديد وارفع كل هذه الملفات كما هي (حافظ على بنية المجلدات، خصوصًا `.github/workflows/`).

### 2. إضافة الأسرار (Secrets)
اذهب إلى: **Settings → Secrets and variables → Actions → New repository secret**، وأضف:

| الاسم | القيمة |
|---|---|
| `WP_URL` | رابط موقعك، مثال: `https://nabdalmalaeb.com` |
| `WP_USERNAME` | اسم مستخدم ووردبريس (له صلاحية نشر) |
| `WP_APP_PASSWORD` | كلمة مرور تطبيقات من: ووردبريس → المستخدمون → الملف الشخصي → Application Passwords |
| `GEMINI_API_KEY_1` | مفتاح أول من [Google AI Studio](https://aistudio.google.com/apikey) |
| `GEMINI_API_KEY_2` | مفتاح ثانٍ احتياطي (يُفضّل من حساب Google مختلف لحصة منفصلة) |
| `TELEGRAM_BOT_TOKEN` | توكن البوت من BotFather |
| `TELEGRAM_CHAT_ID` | معرف قناتك أو الدردشة المستقبلة للتقرير |

### 3. التشغيل
- يعمل تلقائيًا كل ساعة عبر GitHub Actions (`.github/workflows/hourly.yml`).
- يمكنك تشغيله يدويًا فورًا من تبويب **Actions → نشر أخبار 365scores كل ساعة → Run workflow** للتأكد أن كل شيء يعمل.

## بنية المشروع

- `config.py` — كل الإعدادات القابلة للتعديل (التصنيفات، التوقيتات، نافذة الفحص).
- `rules_ar.md` — قواعد الصياغة العربية المرسلة لـ Gemini (لا تُلمس إلا لتعديل أسلوب الكتابة).
- `scraper.py` — سحب قائمة الأخبار وتفاصيل كل خبر (نص + صورة بارزة).
- `rewriter.py` — استدعاء Gemini مع التبديل التلقائي بين المفتاحين عند الفشل.
- `wordpress_client.py` — رفع الصورة، تحديد التصنيفات، نشر المسودة.
- `dedup.py` — منع تكرار النشر (رابط + تشابه عنوان)، مع السماح بإعادة محاولة الأخبار الفاشلة.
- `telegram_notify.py` — إرسال تقرير نهاية كل دورة.
- `main.py` — يربط كل شيء ببعضه، وهو ما يُشغَّل من GitHub Actions.
- `state/seen_articles.json` — سجل الأخبار المنشورة (يُحدَّث ويُحفظ تلقائيًا في المستودع كل دورة).

## نقاط مهمة تحتاج انتباهك عند أول تشغيل حقيقي

365scores موقع مبني بتقنية تصعب معاينتها دون تشغيل فعلي على الإنترنت، لذلك:

1. **استخراج قائمة الأخبار** (`scraper.py` → `get_recent_articles`) يعتمد أولًا على قراءة
   بيانات JSON مضمّنة في الصفحة (`__NEXT_DATA__`)، وإن لم يجدها ينتقل تلقائيًا لطريقة احتياطية
   تبحث عن روابط `/ar/article/...` أو `/ar/news/...` مباشرة في الصفحة.
   إذا رجعت الدورة الأولى بصفر أخبار رغم وجود أخبار فعلية على الموقع، غالبًا بنية الصفحة
   تحتاج تعديلًا بسيطًا في هذه الدالة تحديدًا — أرسل لي أول Log من GitHub Actions وأصلحها معك.
2. **الصورة البارزة** تُستخرج من وسم `og:image` في صفحة كل خبر — هذه الطريقة تعمل على الأغلبية
   الساحقة من المواقع الحديثة بصرف النظر عن التصميم الداخلي، وهي الأكثر ثباتًا.
3. عند حصول خطأ 403 عند رفع الصورة، الكود يرسل `User-Agent` و`Referer` لتفادي حماية hotlink؛
   إن استمر الفشل من مصدر معيّن سيُتجاهل الخبر فقط (كما طلبت) دون توقف بقية الدورة.

## التصنيفات

القائمة مأخوذة من لوحة ووردبريس كما هي:
ريال مدريد، برشلونه، ليفربول، مانشستر يونايتد، مانشستر سيتي، تشلسي، ارسنال، بايرن ميونخ،
باريس سان جرمان، ميلان، يوفنتوس، انتر ميلان، بروسيا دورتموند، اتليتكو مدريد، سوق الانتقالات.

مستبعدان دائمًا: **اهم الاخبار**، **مقالات وتحليلات**.
يُختار دائمًا في كل خبر: **Uncategorized** (خاص بقسم الرئيسية).
لا يُنشئ الكود أي تصنيف جديد أبدًا.
